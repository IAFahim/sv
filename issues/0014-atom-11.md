# Issue 0014 — Atom 11: Game/Frame composition layer (`Sv.Compose`)

Status: closed (2026-11-26, execution record of the sv 2.1 engine, removed in db8dbac on 2026-11-14)

Filed as GitHub issue #14 (closed — execution record). Labels: `ai`, `area:compose`, `kind:feat`.
Contract touchpoint: new clauses 18–19 — bus 0029 (contract v1.0.4, pending ack).

## Problem

- Clause 7's frozen order is the most valuable thing sv owns, yet every host
  re-implements it as a ~40-line harness (`tests/Sv.NorthStar/NorthStarHarness.cs:
  189-234`) — and gets the host duties wrong at their peril (clause 13b effect-column
  zeroing, applied post-emit zeroing, writer discipline).
- The user-facing pain this answers: "where did `WalkTrackTimeline` come from" —
  generated tl pairs and kernel facades plug into user code with no declared home.
  The composition layer is that home, and the only one.

## Plan

- New package `Sv.Compose` — **the only sv package permitted to reference tl and
  ecs-kernels** (`Sv` core stays dependency-free, clause 8 unchanged).
- `Game.Create(schema, capacity)` builder → `.Event<T>()` → `.Timeline<TStep>()` →
  `.Kernel<TStep>()` → `.Build(world, input)`; capacity rounds per issue 0011.
- `Frame.Run(float dt)` encodes clause 7 verbatim as its method body:
  `Capture → Drain(+Reconcile per 0013) → RunIntrinsics/Recalculate →
  ZeroEffectColumns → Timeline.Apply/Advance → Kernel.Run → Conditions.Run →
  EmitFromApplied(+auto-zero) → Swap`. Each step is one line calling an existing
  public primitive — the frame owns order and host duties, never math.
- Timeline/Kernel hooks are generic structs (`struct WalkStep : ITimelineStep`)
  with static-generic dispatch — Burst-friendly, no boxing, no virtual calls; the
  tl 1.3/2.0 naming seam (`OnActive`/`ExecuteActive`, `ApplyLanes`/`ApplyChunk`)
  is absorbed here and nowhere else.
- All state allocated at `Build`; zero warm allocations on `Frame.Run`.
- Manual primitives remain public and contract-valid — the frame is sugar, not a cage.

## Acceptance gate

- New sample-style test: a full game loop driven solely by `Game` + `Frame.Run`
  (spawn, intrinsics, one timeline, one kernel, one event channel) with zero
  handwritten frame-order code; digest asserted against the equivalent manual
  NorthStar-style loop (bit-identical).
- Warm-path allocation receipt: 0 B over ≥ 2,000 frames.
- `sv.slnx` green default + `SV_CHECKED`; FMA grep clean; `Sv` core project still
  references nothing (test enforced).

## Execution receipts

- Landed: `src/Sv.Compose` (net10.0, references `Sv` + `Tl.Runtime` 1.3.0 — the only sv package
  permitted either; `Sv` core untouched and still reference-free, now enforced by
  `CoreDependencyTests` parsing the csproj).
- Builder: `Game.Create(schema, capacity).Event<T>().Timeline<TStep>().Kernel<TStep>().Build(world, input)`
  → `GameHost<…>` exposing `.Game` (state) and `.Frame.Run/Tick`. Chain links prepend
  (`EventLink<T, TNext>`, `TimelineLink<TStep, TNext>`, `KernelLink<TStep, TNext>`, terminal
  `Chain`), so dispatch is static-abstract interface members resolved through generic
  instantiation — zero boxing, zero virtual dispatch, no runtime step storage. Timeline/kernel
  hooks are static abstracts exactly per the issue; the host hook (`IFrameWorld`: Reconcile /
  DispatchEvent / RunIntrinsics / RunConditions) is an instance method set on a
  `struct`-constrained type parameter (constrained calls — direct, devirtualized; state flows
  through reference fields, matching how Burst host structs work).
- `Frame.Run(dt)` encodes clause 7 verbatim, each step one line: drain (`TryReadNext` →
  `DispatchEvent`) → `Reconcile` → `RunIntrinsics` → `Board.Recalculate()` → per timeline
  (zero effect column → `Apply` → `Transform` → `Advance`) → kernels → `RunConditions` →
  `Swap`. `Tick(dt, axes, buttons)` = capture + run. Frame owns order and host duties only —
  no math moved into the frame.
- tl seam absorbed: all tl calls live in `TimelineStep<TTrack, TClip>.Apply/Advance`; user steps
  (`ITimelineStep`) never name a tl API. Kernel hooks receive the host world via generic
  `Run<THost>`; recovering the concrete host inside a generic hook is
  `Unsafe.As<THost, TConcrete>` (reinterpretation, no boxing).
- Game state allocated at `Build`: board (capacity word-rounded), event streams, timeline
  ids/clocks (capacity-sized `ushort[]`), one effect column per timeline step, applied column
  (`int*`, conditions hook re-zeroes after emit-from-applied), channel registry.
  `Channel<T>()` re-fetches the typed channel. Manual primitives remain public — the frame is
  sugar, not a cage.
- New `tests/Sv.NorthStar/ComposeTests.cs`: `FrameRun_MatchesManualNorthStarLoop_BitIdentical`
  — spawn + intrinsics + one timeline (jump.tlb) + one kernel + two event channels driven
  solely by `Game`/`Frame.Tick` with zero handwritten frame-order code, every digest field
  (position/velocity/y/stat columns bits, mana, applied, landed, event log) asserted equal
  against the manual `NorthStarHarness` loop per tick; `FrameRun_WarmPathAllocatesZeroManagedBytes`
  — 0 B over 2,000 `Tick`s (16 warmup) including the tl pair.
- Deviations recorded: `Frame.Run(dt)` stays; live capture rides `Tick(dt, axes, buttons)`
  (raw input bits are per-frame data — replay per issue 0016 re-captures from the ring and
  calls `Run`); nested runner type is `FrameRunner` (property `Frame` keeps `game.Frame.Run`
  shape); `.Event<T>()` registers the payload and the frame owns the two-buffer drain loop,
  while payload interpretation stays on the host (`DispatchEvent` id switch) — static-abstract
  drain handlers would require unprovable constraint accumulation over open chains.
