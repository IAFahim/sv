# Issue 0013 — Atom 10: Reconcile + fused chunk windows (fragmentation heals)

Filed as GitHub issue #13 (closed — execution record). Labels: `ai`, `area:adapter`, `kind:feat`.
Contract touchpoint: clause 5/7 amendments — bus 0029 (contract v1.0.4, pending ack).

## Problem (audit receipts)

- Both hosts delete by swap-with-last-row: Frent `Archetype.DeleteEntity`
  (`Frent/Core/Archetypes/Archetype.cs:253-308`) moves the last row's components
  into the vacated slot via `ComponentBufferManager.Delete`
  (`ComponentBufferManager.cs:196-206`); Unity gives no within-chunk row-order
  stability across structural changes either.
- One deletion therefore breaks `ChunkSeam.TrySlotRange` contiguity for that
  archetype **forever** — the hole never heals, and every subsequent frame pays the
  `Pull` → walk → `Push` remap (demonstrated in `sv-examples/samples/FrentEcs/
  Program.cs:79-88`). The "fast path" is really the append-only-populations path;
  on Frent the remap is O(archetype) because a chunk is the whole archetype buffer.
- Today the host hand-branches `TrySlotRange` vs Pull/Push in every driver loop.

## Plan

- `Sv.Frent.Population` (promotion of `FrentBoard`): owns the query, `Bind`/
  `Unbind`, and exposes chunk windows:
  `foreach (var win in population.Chunks<TColumn>()) win.Apply(board, delta, clamp, applied);`
  — internally fuses `TrySlotRange` fast window and Pull/walk/Push remap; never
  throws for slot fragmentation (the throw survives only for unsupported shapes,
  e.g. non-int-sized columns). Manual `ChunkSeam` stays public.
- `Board.RenumberSlots(ReadOnlySpan<int> oldToNew, int count)` — the core verb for
  slot compaction: rewrites set members, modifier lists, dirty queue, live bits, and
  sv-owned columns; external bindings are invalidated per issue 0012.
- `Population.Reconcile()` — called at the drain step (the structural-change
  boundary clause 7 already freezes): per fragmented archetype, reassign `SvSlot`
  ids ascending, invoke `Board.RenumberSlots` once for the global permutation, and
  return the permutation for host-owned columns; helper `Sv.Columns.Permute<T>(T*
  column, ReadOnlySpan<int> oldToNew, int count)` applies it.
- `RunEnabledChunk` windows participate: reconcile restores 64-alignment per
  archetype.

## Acceptance gate

- Test: 256 bound, delete every 3rd, first post-delete frame uses the fused window
  (correct values asserted against per-entity oracle); `Reconcile()` runs;
  subsequent frames take the contiguous fast path again (probe instrumentation or
  counter asserted).
- Test: `RenumberSlots` preserves stat folds bit-exactly (modifiers, members, dirty
  sets survive the permutation; digest over slot space identical pre/post reorder).
- Test: host column permutation via `Columns.Permute` matches a scalar oracle.
- Full suite green default + `SV_CHECKED`; warm alloc zero; FMA grep clean.

## Execution receipts

- Landed: `Sv.Frent.Population` (owns the query + bind/unbind, wraps `FrentBoard`);
  `population.Chunks<TColumn>()` yields ref-struct windows (zero-managed-alloc foreach)
  whose `Apply(board, delta, clamp, applied)` fuses the `TrySlotRange` fast window and the
  Pull/walk/Push remap (per-row `Clamp.Apply` over the slot-indexed scratch, applied
  row-indexed on both paths). `ApplyEnabled` fuses the words-span enabled verb on both
  paths, including the seam-level `Guard.EnabledTail` rule on the fast path; the remap
  path masks per-row against the slot-space window and never throws for fragmentation.
  Non-int-sized columns still throw (only surviving shape throw). `FastPathChunks`/
  `RemapChunks` counters reset per enumeration (probe surface). Manual `ChunkSeam` public
  and untouched.
- `Board.RenumberSlots(ReadOnlySpan<int> oldToNew, int count)`: validates count ==
  LiveCount, map length == capacity, and that live slots map to distinct targets in
  [0, capacity) — gaps are legal (reconcile's 64-alignment padding). Moves `PairMods`/
  `pairSet` with the pairs, renumbers set members via `SetTable.RenumberMembers`,
  rebuilds the dirty queue (all live pairs re-enqueued — Recalculate after), rebuilds
  live bits, permutes sv-owned columns (dead rows zeroed), rebuilds the free list so
  Acquire still returns the lowest free slot, and invalidates external bindings
  (clause-12 doctrine). Modifier insertion ids ride along → folds bit-exact.
- `Population.Reconcile()` (drain step): enumerates `Query<SvSlot>` chunks, 64-aligns
  each archetype block start (enabled-window geometry), rewrites SvSlot components
  in place through the enumerated span, calls `RenumberSlots` once with the global
  permutation, and returns it for host-owned columns.
- `Sv.Columns.Permute<T>(T* column, ReadOnlySpan<int> oldToNew, int count)`:
  unmanaged-temp scatter (negative entries = dead slots skipped), bounds-checked
  targets, in-place safe.
- Tests: `RenumberTests` (5) — fold/digest bit-exactness across a renumber (Stat +
  sv-owned columns), lowest-free Acquire preserved, bad maps rejected (count mismatch,
  unmapped live slot, duplicate target), Permute vs scalar oracle, out-of-range target
  throw. `PopulationTests` (4) — 256-bound/delete-every-3rd frame 1 remaps with values
  vs per-entity oracle → Reconcile → survivors' slots are exactly {0..170} → frame 2
  takes the contiguous fast path; enabled window heals (values vs slot-parity oracle);
  two-archetype reconcile gives contiguous per-archetype blocks at bases {0, 64};
  windows allocate 0 managed bytes over 2,000 warm frames.

  collection startup raced Frent's component static init (nondeterministic
  TypeInitializationException/'Mana is not initialized'/null-key failures); serialized
  collections make Frent tests deterministic (repo discipline: deterministic order).
- `dotnet test sv.slnx -c Release`: 125/125 + NorthStar 4/4, stable across repeat
