# Issue 0013 — Atom 10: Reconcile + fused chunk windows (fragmentation heals)

Filed as GitHub issue #13 (open). Labels: `ai`, `area:adapter`, `kind:feat`.
Contract touchpoint: clause 5/7 amendments — bus 0029 (contract v1.0.4, pending ack).

## Problem (audit receipts)

- Both hosts delete by swap-with-last-row: Frent `Archetype.DeleteEntity`
  (`Frent/Core/Archetypes/Archetype.cs:253-308`) moves the last row's components
  into the vacated slot via `ComponentBufferManager.Delete`
  (`ComponentBufferManager.cs:196-206`); Unity gives no within-chunk row-order
  stability across structural changes either.
- One deletion therefore breaks `ChunkSeam.TrySlotRange` contiguity for that
  archetype **forever** — the hole never heals, and every subsequent frame pays the
  `Pull` → walk → `Push` remap (demonstrated in `sv-examples/samples/FrentEcs/
  Program.cs:79-88`). The "fast path" is really the append-only-populations path;
  on Frent the remap is O(archetype) because a chunk is the whole archetype buffer.
- Today the host hand-branches `TrySlotRange` vs Pull/Push in every driver loop.

## Plan

- `Sv.Frent.Population` (promotion of `FrentBoard`): owns the query, `Bind`/
  `Unbind`, and exposes chunk windows:
  `foreach (var win in population.Chunks<TColumn>()) win.Apply(board, delta, clamp, applied);`
  — internally fuses `TrySlotRange` fast window and Pull/walk/Push remap; never
  throws for slot fragmentation (the throw survives only for unsupported shapes,
  e.g. non-int-sized columns). Manual `ChunkSeam` stays public.
- `Board.RenumberSlots(ReadOnlySpan<int> oldToNew, int count)` — the core verb for
  slot compaction: rewrites set members, modifier lists, dirty queue, live bits, and
  sv-owned columns; external bindings are invalidated per issue 0012.
- `Population.Reconcile()` — called at the drain step (the structural-change
  boundary clause 7 already freezes): per fragmented archetype, reassign `SvSlot`
  ids ascending, invoke `Board.RenumberSlots` once for the global permutation, and
  return the permutation for host-owned columns; helper `Sv.Columns.Permute<T>(T*
  column, ReadOnlySpan<int> oldToNew, int count)` applies it.
- `RunEnabledChunk` windows participate: reconcile restores 64-alignment per
  archetype.

## Acceptance gate

- Test: 256 bound, delete every 3rd, first post-delete frame uses the fused window
  (correct values asserted against per-entity oracle); `Reconcile()` runs;
  subsequent frames take the contiguous fast path again (probe instrumentation or
  counter asserted).
- Test: `RenumberSlots` preserves stat folds bit-exactly (modifiers, members, dirty
  sets survive the permutation; digest over slot space identical pre/post reorder).
- Test: host column permutation via `Columns.Permute` matches a scalar oracle.
- Full suite green default + `SV_CHECKED`; warm alloc zero; FMA grep clean.
