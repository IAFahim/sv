# Issue 0018 — Atom 15: north-star hygiene (stale oracle name, dead harness fields)

Filed as GitHub issue #18 (closed — execution record). Labels: `ai`, `area:north-star`, `kind:test`.

## Problem

- `ComposeTests.FrameRun_MatchesManualNorthStarLoop_BitIdentical` is a fossil: since
  atom 13 (issue 0016) the "manual" harness rides `Frame.Run` too, so the test compares
  two composed world ports. The true manual-loop oracle is the baked pre-migration
  constants in `MigrationTests`. The name overstates the proof.
- Dead/misleading harness surface kept "for compat" in atom 13: `Gravity` (duplicate of
  `GravityField`, never read), `Dt` (never read — the real dt is `Input.AxisF(0)`, so
  changing `Dt` silently does nothing), and `Ids`/`TickClock` aliasing the game's
  capacity-length arrays while `Entities == 4` (looping `Ids.Length` walks 60 dead rows).
  None of these are in the public surface list recorded in issue 0016's receipts.

## Plan

- Rename the test to what it proves: an independently written world port and the
  migrated harness agree bit-for-bit per tick.
- Delete `Gravity`, `Dt`, `Ids`, `TickClock`; `Initialize` writes
  `host.Game.TimelineIds` directly. `Y` stays (read by `Record()`).
