# Issue 0007 — Atom 6: Frent chunk adapter + Unity handoff record

Filed as GitHub issue #7 (closed — execution record). Labels: `ai`, `area:adapter`, `kind:feat`.

## Shipped surface

`src/Sv.Frent` (package `sv.frent`, references `Sv` + NuGet `Frent 0.8.0-beta` — same
version as the local fork at `/home/i/GitHub/frent-fork`):

- `SvSlot` — the entity→slot mapping lives in ECS storage itself, not a dictionary:
  attaching the component binds, removing unbinds. Per-chunk row→slot lookup is a
  `Span<SvSlot>` walk — no hashing anywhere near a frame path (clause: adapter-owned
  mapping, dense slots).
- `FrentBoard` — `Bind(entity)` = `Board.Acquire` + `entity.Add(SvSlot)`; `Unbind` =
  read slot, `entity.Remove<SvSlot>`, `Board.Release`; `TrySlot(entity, out slot)`.
  Contract: unbind before `entity.Delete()` or the slot leaks (test asserts lifecycle
  density including LIFO reuse).
- `ChunkSeam` — the IJobChunk-shaped seam over `world.Query<T, SvSlot>()
  .EnumerateChunks<T, SvSlot>()`:
  - `TrySlotRange(slots, out start, out count)` — contiguity probe (bulk-bound chunks
    stay slot-contiguous ascending).
  - `RunChunk` / `RunChunk<TColumn, TDelta>` / `RunEnabledChunk` — zero-copy fast
    path: inside `fixed` scopes the ECS span is re-based (`(int*)rows - start`) so
    `board.RunIntrinsicsChunk(value, …, start, count, …)` addresses ECS storage
    directly through slot indexing. Non-slot-contiguous chunks are rejected with a
    diagnostic (never a silent slower path).
  - `Pull` / `Push` — explicit remap seams for fragmented chunks: native slot-indexed
    column ↔ ECS rows, run sv verbs between them.

Frent constraint that shaped the API: Frent 0.8 component storage is managed arrays,
so pointer views are valid only inside a `fixed` scope — `ChunkSeam` runs the board
verbs inside that scope and never returns a raw view. Unity's native-container chunks
do not have this constraint (see handoff).

## Unity Entities 6.7 handoff record (integrator's leg — editor verification)

- `SvSlot` ↔ `public struct SvSlot : IComponentData { public int Slot; }`;
  Bind/Unbind at structural-change boundaries (command buffer / main thread).
- Chunk iteration ↔ `IJobChunk`: `chunk.GetRequiredComponentDataPtrReinterpret<T>`
  gives raw pointers valid for the job's lifetime (native storage — the Frent `fixed`
  re-basing is unnecessary; the re-base arithmetic `(T*)rows - startSlot` is the same).
- `RunEnabledChunk(enabled, offset)` ↔ enableable components
  (`IComponentData : IEnableable`, `chunk.GetEnabledMask()` → 64-bit words; offset =
  chunk's slot base). The tzcnt run-walk consumes the words directly.
- The `Simd.cs` port must keep `BoundsOf` as the explicit chain (NaN → 0, saturate,
  truncate). Burst lowers `(int)float` to saturating fcvtzs on ARM — a raw cast port
  would silently diverge from the pin; the compare/select chain ports verbatim.
- Traps already on record in `contract/NORTH-STAR.md` apply: Burst first-run fallback
  needs a `[BurstDiscard]` canary; package `Tests/` folders are not discovered (use
  `Assets/samples~`); DC0061 requires the Unity.Collections asmdef reference.
