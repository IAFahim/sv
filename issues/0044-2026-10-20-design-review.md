Hidden flaws, concerns, and the shortest path to a rollback-grade, Unity-ready, engine-neutral core.

## 1. Verdict

The foundations are good:

- Columnar slots.
- Content-addressed modifier sets.
- Bit-mask verbs.
- Struct-generic SIMD strategies.
- A tiny IEEE float surface (add, multiply, compare only).
- XXH64 tapes.

That float surface is what makes cross-platform determinism achievable at all.

It is **not yet** a rollback-grade or Unity-grade core. Five things stand between the code and your goals:

1. **The state is managed objects holding raw pointers** (`Board`, `Game`, `InputState`, `EventStreams`). Burst jobs and `ISystem` cannot touch them, and `Compose` needs C# 11 (P-1, P-2).
2. **Intrinsics (HP, mana) are outside every snapshot and every digest** (S-1, D-1). Today the desync detector cannot see the most important numbers in the game.
3. **Snapshots are not minimal, canonical, or safe to load.** They are O(capacity × stats), contain residue and padding, can free memory that a cached `Clamp` still points at, and carry no schema identity (S-2…S-6).
4. **There is no deterministic write path for parallel code** (D-8) and no single door for external mutation (D-6, C-8, C-9).
5. **The set table grows forever and its hash ignores float values** (X-1). This is the one most likely to hurt a long session.

There are also real bugs independent of architecture: an overflow-before-clamp (C-1), a replay-edge bug (C-2), and shared timeline clocks (C-3).

**Do you need to change anything?** Three structural changes make almost everything else easy (§5):

| Change | Removes |
|---|---|
| **State / cache split**: only irreducible state is saved, hashed or sent; sets, mirrors, columns and queues are rebuilt | S-2, S-3, S-4, S-5, X-1 (growth), most of `ReadStats` |
| **Board owns intrinsics, schema declares their bounds** | S-1, D-1 (part), P-3, C-11, the host-captured `Clamp` pointer class of bugs |
| **One door: `Command`, plus generation-checked `EntityRef`** | D-6, C-8, C-9, undo/redo, netcode input, tape, and tests all becoming the same concept |

Everything else is a bug fix.

## 3. Findings

### P — Platform / Unity

#### P-1 [BLOCKER] [read] The simulation state is managed objects, and nothing is reachable from a job

`Board`, `Game`, `InputState`, `EventStreams`, `Channel<T>`, `SvState` and `Schema` are sealed classes holding raw pointers. A Burst job or `ISystem` struct cannot store a reference to them or call their methods. Every verb that matters (`Acquire`, `AddModifier`, `Recalculate`, `Channel.Write`, `Stat`) is therefore unreachable from `IJobEntity`, `IJobChunk` or `IJobFor`. Even `RunIntrinsicsChunk(int*, …)` is an instance method on the managed `Board`.

A job can be handed pointers, but there is no blittable handle type to hand it. `Simd.*` is `internal`, so the best part of the library is not callable on its own.

**Fix:** §5.4 (unmanaged arena, blittable `SvBoardData`) and §7.

#### P-2 [BLOCKER] [env] Language and runtime surface is not Unity-portable

Check each against your target Unity version. If it runs CoreCLR with a modern compiler, the first rows vanish. The Burst rows do not.

| Used | Where | Unity/Burst reality |
|---|---|---|
| `static abstract` interface members (C# 11) | all of `Compose.cs` | Not available at Unity's usual language level (C# 9) |
| `NativeMemory`, `AlignedAlloc` | everywhere | Use `UnsafeUtility.Malloc` / `AllocatorManager` |
| `Vector128/256`, `Avx2.MaskLoad`, `ConvertToInt32Native` (.NET 9) | `Simd*` | Burst uses `Unity.Burst.Intrinsics` and auto-vectorises simple loops |
| `readonly record struct`, `init`, records | `Schema.cs` | Language-level and shim problems; fine at authoring time, not in jobs |
| `delegate* unmanaged<int,int,T>` makers | `EventStreams` | Burst function pointers are a different mechanism |
| `Interlocked` + `Thread.SpinWait` spinlock | `EventStreams` | Not deterministic under parallel jobs (D-8) |
| `float[]`, `ushort[]` | `Game.TimelineIds/Clocks/effects` | Managed arrays are invisible to Burst |

`EventStreams` already says "C# 9 / Unity portable" in a comment, so the core was written with this in mind. `Compose`, `Schema` and the `Simd` layer were not.

#### P-3 [HIGH] [read] `BindOutput(float*, stride)` presumes a contiguous per-stat array

The binding model needs one stable pointer per stat. Unity ECS (and Frent) store components in per-archetype chunks, and the pointers move on structural changes. Your Frent adapter copes by carrying `SvSlot` in a component and falling back to Pull/walk/Push when a chunk isn't slot-contiguous.

In Unity that fast path almost never triggers. Chunk capacity is not a multiple of 64, chunk order is not slot order, and `Reconcile` cannot control where Unity places entities. Expect the remap path (two extra passes over the data) every time.

**Fix:** the board owns the columns, indexed by slot. ECS carries only the slot (§5.5).

#### P-4 [HIGH] [read] Lifetime and safety

- No finalizers or `SafeHandle`s.
- An exception mid-frame, an Editor domain reload, or Enter-Play-Mode-without-reload leaks native blocks.
- Raw pointers are invisible to Unity's job safety system, so races in Editor go undetected.

**Fix:** Editor-only `AtomicSafetyHandle` wrappers, a leak tracker over every persistent allocation, and idempotent `Dispose` everywhere (C-4).

#### P-5 [MED] [env] Deep generic chains duplicate what Unity already provides

`KernelLink<A, KernelLink<B, …>>` and `GameHost<TEvents, TTimelines, TKernels, THost>` create a new instantiation per composition. IL2CPP bounds recursive generic depth (a tunable, with a small default). Unity already orders systems with `[UpdateBefore]` / `[UpdateAfter]`.

Inside Unity, `Compose` is redundant. Keep it as the reference host for non-Unity use, and do not port it.

### S — State, snapshot, rollback

#### S-1 [BLOCKER] [read] Intrinsics are not in the state

Intrinsic values (HP, mana, cooldown counters) live in host columns that sv only operates on through `RunIntrinsicsChunk(int* value, …)`. `Game.SaveState` says so: "The host world's own columns are the host's to save."

- The two blobs (sv state, host state) must be coherent by construction. Nothing verifies they were captured at the same tick.
- The digest does not cover intrinsics (D-1), so HP divergence between peers is invisible.
- `IntrinsicDef.Min/Max` is declared in the schema but nothing in the pasted code applies it (C-13). Bounds are re-supplied at every call site through a `Clamp`.

**Fix:** §5.5.

#### S-2 [BLOCKER] [read] Rollback can free memory a cached `Clamp` still points at

`Clamp.StatMirror*` stores the raw pointer returned by `Board.MirrorBounds(stat)`. `Board.ReadStats` does this:

```csharp
if (state.Read<byte>() == 0)
{
    if (mirrors[stat] != null)
    {
        NativeMemory.Free(mirrors[stat]);
        mirrors[stat] = null;
    }
    continue;
}
```

1. Snapshot at tick 0, before any mirror exists.
2. Run frames. A kernel builds `Clamp.StatMirror(...)` and caches it. The pointer is P.
3. `LoadState(tick0)` frees P.
4. The next frame's cached clamp reads freed memory. Writes go through the SIMD verbs, so any column adjacent to the freed block is at risk.

It is safe only if every `MirrorBounds` call precedes the oldest snapshot you will ever load. That invariant is not enforced anywhere.

**Fix:** never allocate or free on load. Allocate mirrors eagerly for every stat the schema references as a bound, or make mirrors part of the derived cache (§5.1). Better still, remove host-held pointers by letting schema-declared bounds be read internally (§5.5).

#### S-3 [HIGH] [read] `LoadState` leaves externally bound columns stale

Sv-owned columns are restored. External columns still hold the abandoned future. The restored `PairMeta` and sets say "already broadcast", so nothing rebroadcasts.

**Fix:** `LoadState` calls `table.MarkStatDirty(stat)` for every bound stat. The sets store `Computed`, so the next `Recalculate` rebuilds the bound columns exactly. Bound stat columns stop needing to be saved by the host at all.

#### S-4 [HIGH] [read] Snapshot cost scales with capacity and page width, not with entities

Per touched 4096-slot page, `WriteStats` writes:

- `PairMeta` (12 B) × 4096 × S.
- Per-pair `Count` + `Cap` (8 B) × 4096 × S, once a modifier was ever added in that page.
- Plus whole-board `svColumns` (S × Capacity × 4), `changed` masks, and mirrors (Capacity × 4 each).

Arithmetic for S = 16 and Capacity = 16,384 (4 pages): about 3.1 MB meta + 2.1 MB mod headers + 1 MB columns + up to 1 MB mirrors, roughly **6–7 MB per snapshot**. One snapshot per tick at 60 Hz is about 400 MB/s of memcpy before any game logic.

The tape made the opposite choice (live rows only), so the two serializers disagree on the philosophy.

**Fix:** save only irreducible state (§5.1), with page-granular dirty tracking for the big arrays (§6.1).

#### S-5 [MED] [read, ran for sizes] Snapshot bytes are not canonical

Two logically equal states produce different bytes, so snapshots cannot be hashed, deduped, diffed, or byte-compared in tests.

- `StatEntry` has 3 padding bytes and `Expiry` has 4 (measured: sizes 8 and 24). Both are copied raw from unzeroed `NativeMemory.Alloc`.
- Dead rows keep the previous occupant's output and mirror values.
- Layout depends on history: mod-block `Cap`, set-table capacity, bucket layout, which pages exist.

**Fix:** state/cache split; zero rows at release; fixed-capacity pools; a canonical writer.

#### S-6 [HIGH] [read] No identity or version in snapshots, tapes, or a handshake

- `Board.StateShape` is `(Capacity << 20) ^ (statCount << 8) ^ intrinsicCount`: counts only, XOR-packed into overlapping bit ranges. More than 255 intrinsics spills into the stat-count bits, and (1 stat, 0 intrinsics) collides with (0 stats, 256 intrinsics).
- `InputState` has the same packing problem.
- `EventStreams` checks writer count and the *count* of event types.
- `Game` has no header at all.
- The tape header is magic plus version.

Two builds with the same counts but different stat order, bases, coefficients, or event order load each other's snapshots silently. The event case is worse because ids are assigned in reverse declaration order (D-5): swap two `.Event<T>()` calls and a "compatible" snapshot reinterprets payloads.

**Fix:** `Schema.Hash` (XXH64 over canonical definition bytes: stat names, bases, sources, intrinsic bounds, event type names and sizes, timeline ids). Put it in every snapshot header, in the tape header, and in the netplay handshake. Refuse on mismatch.

#### S-7 [MED] [read] `SvState` cannot round-trip over a wire

There is no `CopyFrom(ReadOnlySpan<byte>)` and no `CopyTo`. `Bytes` returns a span over native memory that dangles after the next write (`Realloc`) or `Dispose`. Late join, rollback acks, and desync dumps all need an owning snapshot type with `{ tick, schemaHash, stateHash, bytes }`.

#### S-8 [MED] [read] No first-class tick

`InputState.Tick` increments only inside `Capture`. `Frame.Run` doesn't touch it. `Board.ExpireModifiers(long tick)` takes a host-supplied tick. Nothing connects them. A snapshot does not know which tick it is, so a ring of snapshots cannot be indexed by tick without an external map.

**Fix:** `Game.Tick` is state, advanced exactly once per `Run`, written into snapshot headers, the digest, and tape frames.

### D — Determinism

#### D-1 [HIGH] [read] The digest is blind to most of the state

`Tape.WriteBody` hashes `board.OutputPtr(stat)`, which is the sv-owned column. When a stat is bound, `Recalculate` writes only the bound column and the owned one stays at its pre-bind value (zeros). A host using `BindOutput`, which is the Frent and Unity pattern, gets a digest that never covers those stats and never complains.

The digest also omits:

- Intrinsics (S-1).
- Modifier lists and expiries.
- Timeline ids and clocks.
- Pending events.
- `Applied`.
- The input ring.
- The tick.

Today it is `f(inputs, live bitmap, sv-owned stat outputs)`.

**Fix:** digest the state, not the cache. Offer per-subsystem sub-digests so a mismatch can be bisected (§6.6).

#### D-2 [HIGH] [read] The digest depends on slot numbering

The body iterates ascending slot order. Peers that reach the same logical world through different spawn/despawn histories hash differently. So do peers whose `Reconcile` order differs (Frent archetype/chunk order is an implementation detail).

This is fine for lockstep or rollback with an identical command stream. It is not fine for server-authoritative play with client prediction, or for late join.

**Fix:** make allocation canonical, so slot assignment is a pure function of the live bitmap (lowest-clear-bit first, §5.4), or hash by stable entity key.

#### D-3 [MED] [ran, read] Float bit patterns differ by platform; Fold can reach Inf/NaN

`Modifier` and `StatDef` validate finiteness on the way in, but `Fold` does not on the way out:

- Stacking `Multi` can overflow to ±Inf (2¹²⁸ is 128 doublings of ×2, reachable through unbounded stacking, A-5).
- Then `Inf * 0` (from a `-1` multiplier) or `Inf - Inf` produces NaN.

On x86_64 the generated NaN is `0xFFC00000` (measured). ARM64 generates `0x7FC00000`. `MarkChanged` and the digest compare raw bits, so you get false desyncs across architectures, and a spurious "changed" flag when a NaN flips sign bit.

Also worth checking [env]:

- Burst and IL2CPP/clang can contract `a*b+c` into FMA unless pinned.
- Flush-to-zero differs on some ARM configurations.

**Fix:**

- Saturate Fold results to ±`float.MaxValue` and canonicalise NaN to a single pattern at broadcast (select, not branch).
- Pin `FloatMode.Strict` on every Burst entry point.
- Keep an x64 vs ARM64 golden-tape job in CI.

#### D-4 [MED] [read] Float sum order is modifier arrival order

`Canonicalize` sorts by `(Kind, insertion id)`. Float addition is not associative. Two peers that add the same modifiers in different orders get different last bits, and the set table cannot dedupe them. A totally ordered command stream hides this. Anything looser does not.

**Fix:** canonical order `(Kind, value bits)`. The multiset, not the sequence, determines the stat. Ids are then needed only for removal. Bonus: more sets are shared.

#### D-5 [MED] [read] ⚠contract Declaration order is reversed everywhere

`Kernel<A>().Kernel<B>()` yields `KernelLink<B, KernelLink<A, Chain>>`, so **B runs before A**. The same holds for timelines (effect index 0 belongs to the last-declared timeline) and events (type id 0 is the last-declared event).

It is deterministic but surprising, and nothing in snapshot or tape records the mapping. If a test pins it, document it loudly. Otherwise reverse in `Build`, so declaration order equals execution order.

#### D-6 [HIGH] [read] External mutations are not recorded

The tape stores inputs only. `Acquire`, `Release`, `AddModifier`, `RemoveSource`, `ExpireModifiers`, and `Channel.Write` performed by host code between frames are invisible. `Playback` reproduces them only if the host regenerates them from inputs plus events. There is also no initial-state keyframe, so playback must start from "the same" fresh host.

**Fix:** the Command door (§5.3) plus keyframes (§6).

#### D-7 [MED] [read] `float dt`

`Run(float dt)` stores `dt` in the tape. Variable timestep is the most common way to lose determinism. Timelines advance in `ushort` ticks while kernels receive `float dt`, which is two clocks.

**Fix:** a fixed tick rate declared in the schema. `dt` becomes a constant or disappears.

#### D-8 [HIGH] [read, env] No deterministic parallel write path

- **Events:** a spinlock per writer, with order equal to lock-acquisition order. `Game` registers every channel on writer 0. `Channel.Writer` is fixed at creation. The usual shortcut, writer = thread index, is nondeterministic, because which worker runs which chunk changes per run.
- **Modifiers:** `AddModifier` mutates shared queue/ids/tables.
- **`Stat()`:** mutates shared `scratch` (C-12).

**Fix:** sort-keyed command buffers and per-range event streams concatenated in key order (§7). That is the same trick as `EntityCommandBuffer.ParallelWriter`.

#### D-9 [MED] [read] `nextInsertionId` is `int`

`++nextInsertionId` is unchecked. Wrap happens at 2³¹ adds:

| Adds per frame (60 Hz) | Time to wrap |
|---|---|
| 1,000 | about 10 h |
| 10,000 | about 1 h |

After wrap, ids go negative, `Canonicalize` reorders folds, and ids collide with the synthetic range `int.MinValue + k`.

**Fix:** `long`, or ids that are only a per-pair sequence (§5.7 makes ids irrelevant to ordering).

### C — Correctness

#### C-1 [HIGH] [ran] ⚠contract The add wraps before the clamp

Every path (SIMD lanes, scalar tail, remap path) computes `before + delta` as an unchecked `int`. Measured:

```
50 + int.MaxValue = -2147483599  →  Constant(0,100)  →  0
```

A "full heal" expressed as `delta = int.MaxValue` kills the target. `delta = int.MinValue` on a negative value wraps upward.

**Fix:** saturating add, then clamp.

- Scalar: do the math in `long`.
- SIMD: `s = a + b`, `overflow = ((a ^ s) & (b ^ s)) < 0`, then select `MaxValue` or `MinValue` by the sign of `b`.
- Test all lane widths with `{int.MinValue, -1, 0, 1, int.MaxValue}²`.
- If the contract defines wrap, put it on the bus first.

#### C-2 [HIGH] [read] `BeginReplay` corrupts button edges

```csharp
new Span<ulong>(previous, ButtonWords).Fill(0);
new Span<ulong>(buttons, ButtonWords).Fill(0);
```

`ReplayStep` then computes `pressed = word & ~previous`. Every button held across `fromTick − 1 → fromTick` reports `Pressed` on the first replayed tick. The original run did not. Rollback re-simulation diverges whenever a held button spans the rollback boundary.

**Fix:** seed `buttons` from the ring entry for `fromTick − 1` when it is still in the ring, otherwise from the snapshot. Never zero.

#### C-3 [HIGH] [env: tl] Shared timeline clocks advanced once per timeline

`Game` has one `TimelineIds` and one `TimelineClocks`. `TimelineLink.Run` calls `TStep.Advance(game)` for each registered timeline. With N timelines the same clock array is advanced N times per frame, and timeline k+1 applies against clocks already advanced by timeline k.

Unless `tl`'s `Advance` is keyed by something not visible here, that is a bug. If each timeline needs independent playback, `Game` needs per-timeline id/clock columns.

Related: `ushort` clocks wrap at 65,535 ticks, which is 18.2 min at 60 Hz or 8.5 min at 128 Hz.

#### C-4 [MED] [read] `Game.Dispose` double-frees

Every other type guards with a `disposed` flag. `Game.Dispose` calls `NativeMemory.Free(Applied)` unguarded. `using var host` plus an explicit `host.Dispose()` frees twice. Add the guard and a finalizer (or `SafeHandle`).

#### C-5 [HIGH] [read] Reconcile has three separate problems

1. **`Game`'s own slot-indexed columns are never permuted.** `TimelineIds`, `TimelineClocks`, `Applied` and every effect column are indexed by slot, but `Board.RenumberSlots` does not know them. `IFrameWorld.Reconcile(Game)` must remember all of them, through `Columns.Permute(T*, …)` (managed arrays need `fixed`). Miss one and entity N plays entity M's clip.
2. **`Columns.Permute` leaves garbage.** `temp` comes from unzeroed `Alloc`. Only mapped indices are written. `column[i] = temp[i]` then copies uninitialised bytes over every 64-alignment padding slot.
3. **`count` means two things.** In `RenumberSlots` and `Population.Reconcile` it is the live count. In `Permute` it is an upper bound on new indices. The natural call `Permute(col, perm, board.LiveCount)` throws as soon as padding pushes an index above `LiveCount`.

Also `Population.Reconcile` is non-atomic. It rewrites `SvSlot` components chunk by chunk, then calls `RenumberSlots`. Padding is applied per **chunk** (up to 63 wasted slots each), not per archetype. A capacity overflow or an unbound live slot therefore throws after the world was already rewritten, and world and board disagree with no way back.

**Fix:** `Game.Renumber(perm)` permutes everything it owns. Zero-fill `Permute`'s temp. Build and validate the whole permutation first, then apply.

#### C-6 [HIGH] [read] Memory-safety guards vanish in release; enabled windows overrun partial tails

`ChunkRange`, `EnabledRange`, `EnabledTail`, `BindingFresh` and `BoundColumnFit` are `[Conditional("SV_CHECKED")]`. The pointer overloads take no lengths. A wrong `start/count` is a silent out-of-bounds write in shipping builds, surfacing as a desync or a crash far from the cause. One always-on range check per call (not per row) is negligible.

There is also a concrete overrun with correct inputs. The enabled-window verbs write `applied` for the entire 64-row window: disabled rows get 0, and all-zero 8-lane groups are zeroed.

- `ChunkSeam.RunEnabledChunk(…, ulong enabled, offsetSlot, …, Span<int> applied)` and `ChunkWindow.ApplyEnabled` pass the board a chunk-sized `applied`. When the last window of a chunk is partial, the zeroing runs past the span.
- `ChunkSeam.RunEnabledChunk(ulong enabled …)` never calls `EnabledTail`. A full-ones word on a partial tail window processes rows beyond the chunk.

**Fix:** size `applied` to the 64-rounded window (or clip stores to the window), and add the tail check to every enabled entry point.

#### C-7 [MED] [read] Spawn visibility

`Release` leaves the slot's output and mirror values. `Acquire` does not clear them. Between `Acquire` and the next `Recalculate`, `Output` shows the previous occupant.

At `Recalculate`, `MarkChanged` compares bits against that stale value. A new entity whose first value equals the previous occupant's (or equals 0 on a fresh column) is not flagged changed. Any reactive consumer of `ChangedWords` misses the spawn.

**Fix:** zero the row at release, and OR an "acquired this tick" mask into `changed`.

#### C-8 [HIGH] [read] Slot reuse without generation

`Release` pushes to a LIFO stack and `Acquire` pops the same slot back. Events carry `int row`; commands and handles carry slots.

- An event emitted on frame N about slot 7 is dispatched on N+1, after slot 7 was released and re-acquired by a different entity.
- `ModifierHandle` is a global id with no slot or stat in it, so `RemoveModifier(slot, stat, handle)` depends on the caller remembering both.

**Fix:** `EntityRef(slot, generation)` wherever data crosses a tick boundary. `Release` bumps the generation.

#### C-9 [MED] [read] Totality: sim-facing operations throw

These throw:

- `Release` of a non-live slot.
- `RemoveModifier` with an unknown handle.
- `Acquire` on exhaustion.
- `SlotLive` failures.

If a message from the network can reach them, a late or malformed packet is a remote crash. If one throws inside `Recalculate`, queue state can be left half-updated. Sim-facing operations should return a status. Exceptions are for setup-time programmer errors.

#### C-10 [LOW] [read] `EventStreams` hardening

- `bytesPerWriter <= 0` is not validated. With capacity 0 the growth loop `capacity *= 2` never terminates, and the writer spinlock is held.
- A failing `Realloc` inside the lock leaves it held.
- Doubling overflows `int` near 1 GiB.
- Arenas never shrink and have no cap. A runaway emitter grows until OOM instead of producing a deterministic "event overflow" signal.

#### C-11 [LOW] [read] `Clamp.Stat*` silently freezes

`Clamp.Stat/StatMin/StatMax` on an sv-owned stat resolve to the owned column with `generation = -1`, which is never checked. If that stat is later `BindOutput`-ed, the owned column stops updating and the clamp reads frozen bounds. `StatMirror` does not have this problem.

#### C-12 [LOW] [read] `Stat()` is a read that writes

`Board.Stat(slot, stat)` runs `Gather`, which mutates `scratch` and `scratchIds` and may reallocate them. It is neither reentrant nor thread-safe. It also returns the **pending** value (including modifiers not yet recalculated), while `Output` returns the **committed** one. Mixed use in one frame gives two answers.

#### C-13 [LOW] `IntrinsicDef.Min/Max` is dead in the pasted code

Only the intrinsic *count* appears (in `StateShape`). Wire it (§5.5) or delete it.

#### C-14 [LOW] `RenumberSlots` leaves `changed` stale

`changed` / `changedTouched` stay indexed by old slots until the next `Recalculate`. `ChangedWords` in between is garbage. Clear them in `RenumberSlots`.

### X — Scale and performance

#### X-1 [BLOCKER] [ran, read] The set table only grows, and its hash ignores values

**(a) Sets are never freed.**

- `SetTable` has no remove, refcount, or compaction.
- `LiveSetCount => setCount` is the total ever created.
- `contentArena` is append-only.
- Each set also owns a `malloc`ed member list.

Every distinct canonical content ever seen persists, in memory and in every snapshot. `MarkStatDirty` and `MemberTotal` are O(sets). Games with continuous or per-entity values (rolled affixes, buffs that decay as `Multi = 0.37 → 0.36 → …`, derived stats whose source is per-entity) mint sets without bound.

**(b) The hash puts values in the wrong bits.** `ContentHash` is FNV-style over 64-bit words `(kind | floatBits << 8)`. Multiplication only carries upward, so the **low 8 bits of the hash depend on the stat and kinds, never on the float values**. Buckets index with `hash & mask`.

Measured, distinct start buckets for 200 sets that differ only in value:

| Values | mask 31 | mask 255 | mask 4095 |
|---|---|---|---|
| `Multi = 5·i`, FNV as written | 1 | 1 | 1 |
| `Multi = 5·i`, with a 64-bit avalanche finalizer | 32 | 137 | 190 |
| `Multi = 0.37·i`, FNV as written | 1 | 1 | 16 |

Tables of 256 buckets or fewer, which is the realistic range, put every same-shape set in one cluster, so `Resolve` is O(sets) per call.

**(c) Growth only at 100% load.** `Resolve` grows buckets only when the probe sequence wraps the entire table. Linear probing at near-full load is slow before every growth.

**Fix:**

- Treat sets as a cache (§5.1): refcount or epoch-rebuild them.
- Add an avalanche finalizer.
- Cap load at about 50%.
- Add a hard cap with a deterministic failure.
- Document the contract "stat inputs come from a small discrete alphabet".

#### X-2 [MED] [read] Spawn is O(stats) hash lookups

Every `Acquire` enqueues all stats. Each pair gathers, canonicalises, hashes, probes, and appends a member. Spawning 10,000 entities × 16 stats is 160,000 queue entries and hash probes, for entities that have no modifiers at all.

**Fix:** a pre-resolved "empty set" per stat so `meta.Set` starts valid, and template sets (spawn with a precomputed set id) for the rest.

#### X-3 [MED] [read] Tape size

The tape writes the full body (every live stat float) next to the digest on every frame. For 10,000 live × 16 stats × 4 B that is 640 KB per frame, about 38 MB/s, about 2.3 GB per minute at 60 Hz. That is reasonable as an `SV_CHECKED` mode and unusable as the default.

**Fix:** digest-only default, keyframes every K ticks, body on demand. `WriteBody` also resolves each stat through `Schema.Stat(name)`, a string dictionary lookup per stat per frame.

#### X-4 [LOW] `Array.Clear(effect)` is O(capacity × timelines) per frame, regardless of live count.

#### X-5 [LOW] `Recalculate` rewrites all members of a freshly folded set after already broadcasting to each joiner. It also does an integer division (`pair / statCount`) per queue entry.

#### X-6 [LOW] The expiry heap keeps entries for modifiers already removed (by handle, source, or release) until their tick passes. Buffs that are re-applied and removed with long durations accumulate.

### A — API and ergonomics

#### A-1 [MED] Overload explosion
There are about 12 public `RunIntrinsicsChunk` / `RunEnabledChunk` overloads (pointer/Span × uniform/column delta × one/many words × with/without applied). Internally you already have the algebra: `IBound`, `IDelta`, `IApplied`, and the width. Expose one generic verb and derive the overloads from it.

#### A-2 [MED] `int` soup
`slot`, `source`, `tick`, `start`, `count`, `delta` are all `int`/`long`. You did this well for `StatId`, `IntrinsicId` and `ModifierHandle`. Extend it to `Slot`, `Tick`, `SourceId`, `EntityRef`.

#### A-3 [MED] [read] Host-world struct semantics
`GameHost.World` is a get-only property returning a struct copy. `FrameRunner.Run` copies it again into a local. Kernels receive `in world`, and interface calls through an `in` generic struct may copy defensively because the compiler cannot know `THost` is readonly.

Any by-value state in the struct (counters, a list header) mutates a throwaway copy. Mutations survive within a frame at best. It works only when the host struct holds pointers and handles exclusively. Make that a type constraint (`unmanaged`, `readonly struct`) or pass the world by `ref`.

#### A-4 [MED] One `Applied` column per game
Two intrinsics (HP and shield) in one frame cannot both leave applied deltas for emit-from-applied. The host must interleave verb → emit → zero. Give applied a per-verb scratch slice, or return it.

#### A-5 [MED] Closed modifier model and unbounded stacking
The model is `Added / Additive / Multi` only. There is no Override/Set, no Min/Max cap, and no stacking policy. `AddModifier` always appends, so re-applying "Rage" every tick grows the list without bound unless the caller dedupes.

**Fix:** add stages `Override`, `Min`, `Max`, and a `StackPolicy` (Stack, Refresh, Replace, Ignore) keyed by `(source, kind)`.

#### A-6 [HIGH] Input is single-player and cannot be corrected
`InputState` has one axes/buttons stream. It has no player index, no confirmed/predicted distinction, and no way to overwrite a past tick when a remote input arrives late. Axes are raw float bits: NaN payloads, `-0`, and 32 bits of bandwidth per axis.

**Fix:** per-player rings, `ConfirmedUpTo`, `Correct(player, tick, input)`, and input quantisation (int16 axes, canonical zero).

#### A-7 [MED] Positional ids
`StatId` is the declaration index. Inserting a stat mid-list renumbers everything silently (see S-6). Add a stable name hash.

#### A-8 [LOW] `Channel<T>` exposes mutable `Id`/`Writer`
`Game.Channel<T>()` is a `Dictionary<Type, object>` cast that throws `KeyNotFoundException`. Return typed readonly channel handles from the builder instead.

#### A-9 [LOW] `Frame.Tick(float, uint*, ulong*)` is pointer-only
Add `ReadOnlySpan` overloads.

## 4. Checked and found sound

Read against the published definitions. I did not run test vectors, except where noted.

- **XXH64** matches the reference algorithm: constants, round, merge, 32-byte loop, 8/4/1-byte tails, avalanche. Endianness is handled.
- **`Clamp.BoundOf` vs SIMD `BoundsOf`**: scalar and vector agree on NaN → 0, saturation on both sides, and truncation toward zero in range.
- **`ClampBoth` vs scalar `Clamp.Apply`**: both compare the original value to `lo` first, so they agree even when `min > max`.
- **`applied` indexing** is row-relative in both the fast path (`appliedPin − start + slot`) and the remap path.
- **Set member bookkeeping**: swap-remove with `meta.Pos` fix-up is correct in both `Recalculate` and `ClearSlotStats`.
- **Derived-stat re-queue converges**: it is driven by `meta.Set` changing, and set identity is content identity.
- **Event double buffer**: read and write arenas are distinct, so `Realloc` of the write arena cannot invalidate payload pointers being dispatched.
- **Hash-collision safety**: `ContentEquals` makes collisions slow, not wrong.
- **Cache-line layout**: each writer's lock and offset share a 64-byte line.
- **Fold ordering**: the three-pass Added → Additive → Multi fold is deterministic given canonical order.

**Keep these in any redesign:**

- The struct-generic strategy pattern in `Simd`.
- Content-addressed sets (as a cache).
- `applied` as the verb's output.
- Typed ids.
- The narrow float surface.
- No managed allocation per frame.
- `ChangedWords` as the one-way edge to views.
- Tape plus XXH64.

## 5. What I would change

### 5.1 Axioms: state versus cache

Everything that is not irreducible is derivable. Save, hash and send only the left column.

| Irreducible state | Cache (rebuild on load, never ship) |
|---|---|
| Live bitmap + per-slot generation | Free list (derive: lowest clear bit) |
| Intrinsic columns | sv-owned stat output columns, mirrors |
| Flag columns (bitsets) | `changed` masks, dirty queue, scratch |
| Modifier multiset per `(slot, stat)`: kind, value, source, expiresAt | Set table, `PairMeta`, bound external columns |
| Pending events | tl effect columns (if recomputed before use) |
| Per-player input rings | |
| Timeline ids and clocks | |
| Tick | |

Rule, as a test: `Load(state); Rebuild()` must equal the cache at save time, bit for bit.

Consequences:

- Snapshots shrink by the whole `svColumns` / `changed` / mirrors / set table / meta pages.
- The digest hashes state only.
- `ReadStats` and `SetTable.Read` (the two hairiest functions, and where S-2 lives) shrink to "read pools, then rebuild".
- The set table can be thrown away and rebuilt every K ticks to bound growth. This is deterministic, because sets cannot influence results: output is `Fold(base, content)`.
- Changing a stat's base or a derived coefficient while a match runs becomes a rebuild instead of a migration.

Cost: a full recalc after load, O(live × stats). Offer both a cache-inclusive fast snapshot (for the local rollback ring) and the minimal canonical snapshot (for hashing, saving and the wire).

### 5.2 The primitives

Five nouns and five verbs are enough to express every mechanic in §8.

| Noun | Meaning |
|---|---|
| **Column** | `int` per slot with schema-declared bounds (intrinsic) |
| **Flag** | one bit per slot (64 per word): tags, immunities, states |
| **Modifier multiset** | per `(slot, stat)`: `Fold` gives the stat |
| **Log** | typed append-only events, consumed next tick |
| **Clock** | the tick, plus expiries |

| Verb | Meaning |
|---|---|
| **Apply** | saturating add → clamp → `applied` (also `Spill`: the requested − applied remainder) |
| **Grant / Revoke** | multiset ± with a stack policy |
| **Select** | mask algebra over entities: `alive & poisoned & ~immune` |
| **Emit** | mask → log, in slot order |
| **Step** | the fixed-order schedule |

`Select` is the unifying idea. Your verbs already take `ulong` enabled words. Make flag columns first-class and "which entities does this affect" becomes bitwise ops on 64 entities at a time: branchless, total, deterministic.

Laws worth encoding as property tests:

- `clamp(clamp(x)) = clamp(x)`.
- `Revoke ∘ Grant = id` on `Fold`.
- `Fold` depends on the multiset only.
- Emit order = slot order.
- `Step ∘ Load ∘ Save = Step`.

### 5.3 One door: `Command`

All outside-to-sim mutation (player input, network messages, scripts, editor actions, undo/redo) goes through one typed, total, serialisable value. Events stay system-to-system.

```csharp
public enum CommandKind : ushort
{
    Spawn,
    Despawn,
    Apply,
    Grant,
    Revoke,
    SetFlag,
    ClearFlag,
}

public enum CommandResult : byte
{
    Applied,
    StaleTarget,
    Rejected,
    Exhausted,
}

public readonly struct Command
{
    public readonly CommandKind Kind;
    public readonly EntityRef Target;
    public readonly ushort Id;
    public readonly int Operand;
    public readonly uint SortKey;
}
```

The same queue is what the network sends, what the tape records, what undo/redo logs, what tests drive, and what a parallel job writes through `ParallelWriter` with `SortKey`. Applying a command validates the generation (C-8) and returns a status (C-9). It never throws.

Commands are applied at the **start** of the tick they are stamped with. Do not route them through event latency.

### 5.4 Arena: state is bytes

Fixed capacities declared up front (`SvLimits`). One native block. References are `int` offsets or indices, never pointers.

- **State region first, cache region second.** `Save` is one `memcpy` of the state region. `Load` is the inverse plus `Rebuild`. `Hash` is XXH64 over the same bytes. `Fork` is a `memcpy` into another arena.
- **Fixed-capacity pools** replace `malloc`ed `PairMods` blocks, page tables, growable set tables and heaps:
  - Modifier pool: SoA `kind[] value[] source[] id[] expires[] next[]`, with a head index per `(slot, stat)`.
  - Expiries: a timing wheel keyed by tick, or a sorted pool. Both are canonical.
  - Overflow is a deterministic status plus an event, never a silent `Realloc`.
- **Lowest-free-first allocation** (`TZCNT` over `~live`) deletes `freeSlots` and the LIFO reuse. Slot assignment becomes a pure function of the live bitmap (fixes D-2), snapshots shrink, and `Reconcile` is needed much less because the slot space stays dense. Pair it with generations (C-8), because immediate reuse of the lowest slot makes stale references more likely.
- **Zero on release.** Rows and pool entries are zeroed when freed, so state bytes are canonical (S-5).
- **Blittable header** with magic, schema hash, tick and region offsets: `Burst`-friendly, relocatable, wire-ready.

### 5.5 Board-owned intrinsics, schema-declared bounds

```csharp
var schema = SchemaBuilder.Create()
    .Stat("max_hp", 100f)
    .Stat("armor", 0f)
    .Intrinsic("hp", min: 0, maxStat: "max_hp")
    .Intrinsic("shield", min: 0)
    .Flag("poisoned")
    .Flag("immune")
    .Build();

var hp = schema.Intrinsic("hp");

board.Apply(hp, slot, -12);
board.ApplyMasked(hp, wordIndex, enabledWord, -3);
board.ApplyAll(hp, deltaColumn);
```

- The bound is read internally from the mirror (or constant), so no `Clamp` object leaks pointers. That removes S-2, C-11, and the "frame-frozen bounds" capture problem.
- Intrinsics and flags are in the state (S-1), in the digest (D-1), and in the snapshot with no host cooperation.
- ECS carries `SvSlot` and reads values through the board. The ECS side becomes a **projection**, so it never needs snapshotting (§7).
- `IntrinsicDef.Min/Max` stops being dead metadata (C-13).
- Contract-pinned signatures (`RunIntrinsicsChunk(int* value, …)`) can stay as the low-level layer. Add the schema-bound verbs on top, via the bus.

### 5.6 Entity identity

```csharp
public readonly struct EntityRef
{
    public readonly int Slot;
    public readonly uint Generation;
}
```

- `Release` bumps the generation.
- Events, commands, modifier handles and `source` ids carry `EntityRef`.
- `ModifierHandle` becomes `(slot, stat, id)` so it is self-describing.

### 5.7 Deterministic fold

- Canonical order: `(Kind, valueBits)`.
- Stages: Added → Additive → Multi → Override → Min → Max.
- Saturate to ±`float.MaxValue`.
- Canonicalise NaN.
- Ids only for removal, and 64-bit.

## 6. Rollback, snapshots, undo/redo, multiplayer

### 6.1 Snapshot ring

- Depth = max rollback + 1.
- Capture once per tick after the state/cache split (a few hundred KB for typical boards, versus 6–7 MB today).
- For large boards, track dirty 4 KB pages with a bitmap, and capture only the dirty pages (delta ring).
- Compress for the wire. The state region is mostly zeros, so LZ4 or zstd gets large ratios.

### 6.2 Rollback driver

```csharp
public sealed class RollbackSession
{
    public void Advance(InputFrame local)
    {
        inputs.Record(localPlayer, now, local);
        inputs.PredictRemote(now);
        ring.Capture(now, sim);
        sim.Step();
        now = now.Next();
    }

    public void Correct(PlayerId player, Tick tick, InputFrame real)
    {
        if (!inputs.Differs(player, tick, real))
        {
            return;
        }

        inputs.Overwrite(player, tick, real);
        firstBad = Tick.Min(firstBad, tick);
    }

    public void Resimulate()
    {
        if (firstBad.IsNone)
        {
            return;
        }

        ring.Restore(firstBad, sim);
        for (var t = firstBad; t < now; t = t.Next())
        {
            SubmitInputs(t);
            sim.Step();
        }

        firstBad = Tick.None;
    }
}
```

It needs these fixes first:

- C-2: replay edges.
- A-6: per-player rings with overwrite.
- S-8: tick in state.
- S-1: intrinsics in state.

### 6.3 Undo / redo

Keyframes every K commands plus a command log.

```csharp
public sealed class History
{
    public CommandResult Do(in Command command);
    public bool Undo();
    public bool Redo();
}
```

- `Do` appends at the cursor and truncates the redo suffix.
- `Undo` moves the cursor back, restores the nearest keyframe at or before it, and replays commands up to the cursor. Cost is at most K commands.
- `Redo` re-applies one command.
- In a networked game, "undo" is not a sim feature. Express it as a new compensating command, or as a rollback that every peer agrees on.

### 6.4 Late join, spectate, save games

Snapshot plus inputs since. The schema hash is checked on load. Save games are snapshots.

### 6.5 Lag compensation

`Fork()` the arena into a scratch simulation, load the target tick, and validate the hit there. The live simulation is untouched.

### 6.6 Desync bisection

Sub-digests: `board`, `intrinsics`, `flags`, `modifiers`, `events`, `inputs`, `timeline`, plus a digest per 64-slot word. On mismatch you get the first differing subsystem, then the first differing word, then the slot. Peers exchange `(tick, digest)` every N ticks and fetch a snapshot from the authority on mismatch.

## 7. Unity ECS: `IJobEntity` / `IJobChunk` / `ISystem`

Use sv as the **simulation database** and ECS as input and view. Do not mirror the Frent two-way chunk fusion. Unity chunk order is not slot order, so the fast path never triggers (P-3).

| sv | Unity |
|---|---|
| Board / arena | `unsafe struct SvBoardData` behind a singleton `IComponentData`, freed in `OnDestroy` or via `ICleanupComponentData` |
| Slot | `IComponentData SvSlot { int Index; uint Generation; }` |
| Schema | `BlobAssetReference<SchemaBlob>` baked from authoring. Strings exist only at bake time. A source generator emits typed `StatId` constants. |
| Verbs over windows | `IJobFor` / `IJobParallelFor` over 64-slot **words**. Windows are disjoint, so results are independent of worker count. |
| `Recalculate` | `ISystem`: parallel gather/hash into per-word buffers → serial intern in pair order → parallel broadcast |
| Commands | `SvCommandBuffer.ParallelWriter` with `SortKey`; one system sorts and applies them deterministically |
| Events | per-word-range streams (`NativeStream`-style), concatenated in index order |
| Input | `IInputComponentData` per player → quantised `InputFrame` → `InputState` |
| Tick | `FixedStepSimulationSystemGroup` with a fixed timestep. Never `SystemAPI.Time.DeltaTime`. |
| View | A system reads `ChangedWords` and writes presentation components. One-way, O(changes), nothing to snapshot. |

Rules:

- **Never use `Entity.Index`, `Entity.Version`, chunk index, or iteration order as a determinism key.** They are allocation-order dependent. Use `SvSlot` or an explicit spawn sequence number.
- Writes from parallel code go through the sort-keyed command buffer. Reads happen only in phases where no writer runs.
- Pin `[BurstCompile(FloatMode = FloatMode.Strict, FloatPrecision = FloatPrecision.Standard)]` on every sv entry point. Check your Burst version's docs on whether `Deterministic` is implemented. Hash golden tapes on x64 and ARM64 in CI regardless.
- Order the `ISystem`s with `[UpdateBefore]` / `[UpdateAfter]` to mirror the frame schedule: commands → events → intrinsics → recalc → timelines → kernels → conditions → swap. This replaces `Compose`.
- Editor builds wrap every pointer in an `AtomicSafetyHandle` and run a leak tracker (P-4).
- **Netcode for Entities:** it rewinds ghost components, not your native arena. Two rollbacks fighting each other is the worst outcome. Pick one authority. Either own the rollback (GGPO-style) and treat ECS as a projection, or put the sv state inside Netcode's prediction loop explicitly. For lockstep or rollback, take the first.
- Targets: a `netstandard2.1` / C# 9 core with `#if` gated SIMD and a `Sv.Unity` package for the adapter. Compose stays on modern .NET for non-Unity hosts.

## 8. Mechanics from primitives

| Mechanic | Composition |
|---|---|
| Damage with shield | `Spill(shield, −d)` → remainder → `Apply(hp, −remainder)` |
| Poison / DoT | `Flag poisoned` → `Select(alive & poisoned & ~immune)` → `Apply(hp, −n)` each tick |
| Heal over time | the same with `+n`; bounded by the schema's `hp ≤ max_hp` |
| Lifesteal | `applied` from the damage verb feeds `Apply(attackerHp, +applied·ratio)` |
| Buff / debuff | `Grant(slot, stat, modifier, source, expiresAt)`; `Revoke` by source |
| Aura | `Grant` with `source = auraEntity` to every entity in range; `RevokeSource` when it leaves |
| Stun / root | `Flag` + `Grant(speed, Multi −1)` or `Override 0` |
| Immunity / invulnerable | `Flag immune` excludes the entity from damage masks |
| Cooldown | intrinsic `cd` with `Apply(cd, −1)` clamped to `[0, max]`; `Emit(Ready)` on the transition |
| Level-up | `Grant` permanent modifiers with `source = Level` (the set table dedupes identical templates) |
| Unit templates | a spawn-time set of `Grant`s resolved to one precomputed set id (X-2) |
| Death | `Emit` where `hp == 0`, applied at tick boundaries; `Despawn` as a command |
| Buff stacking caps | `StackPolicy` on `Grant` (A-5) |
| Crit / resist | stat `Fold` for the multiplier; the damage pipeline is an ordered list of `Apply`/`Spill` stages |

```
Alloc(1000, 8)  usable bytes >= 8008      (two-arg overload multiplies)

FNV bucket spread, 200 sets of Multi = 5*i:  mask 31 -> 1, mask 255 -> 1, mask 4095 -> 1
with avalanche:                              mask 31 -> 32, mask 255 -> 137, mask 4095 -> 190
```

The two-argument `NativeMemory.Alloc/AllocZeroed(n, m)` finding is systemic: `Alloc<T>(count)` in `Board.Stats`, `SetTable` and `Columns`, the `EventStreams` arenas, the `InputState` ring, and the tape body. Each allocates `n × m` bytes, so blocks are 4×–24× larger than intended until a `Realloc` shrinks them. That is memory-safe but wrong. `Board.MemoryBytes` undercounts real usage, and the alignment you thought you had is not requested. It is a porting trap too: `UnsafeUtility.Malloc(size, alignment, allocator)` does take an alignment, so the intent will be silently right in Unity and silently wrong now.

## 11. Test oracles to add

1. **Round trip:** `Save → Load → Save` produces identical bytes (after canonicalisation).
2. **Split-run equivalence:** run `a + b` ticks, versus run `a`, save, run `b`, load, run `b`. Same digest.
3. **Cache rule:** `Load(state); Rebuild()` equals the cache at save time.
4. **Reference model:** random sequences of Acquire / Release / Grant / Revoke / Expire / Renumber / Save / Load against a dictionary-based model in canonical order. Compare every output and the digest.
5. **Thread-count independence** once parallel: 1, 2 and 7 workers give the same digest.
6. **Cross-arch golden tapes:** x64 and ARM64, managed and Burst.
7. **Overflow lattice:** the saturation test from atom 1.
8. **Poison on free:** in tests, fill freed native blocks with `0xDD` and run rollback with cached clamps. This catches S-2.
9. **Hash spread:** N sets with round-number values must spread across buckets.
10. **Hostile commands:** fuzz stale, out-of-range, and double-release commands. No throw, and no state change beyond the returned status.
