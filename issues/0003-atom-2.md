# Issue 0003 — Atom 2: stats, canonical fold, content-dedup sets, broadcast, Clamp.Stat

Status: closed (2026-11-26, execution record of the sv 2.1 engine, removed in db8dbac on 2026-11-14)

Filed as GitHub issue #3 (closed — execution record). Labels: `ai`, `area:core`, `kind:feat`.

## Problem

The composition contract's stats layer: float stats with modifiers folded in canonical
order (clause 3), content-deduped so identical modifier sequences fold once and
broadcast to every member (clause 4), `BindOutput` column binding, `Clamp.Stat`
resolving to bound output columns (clause 10), and the StrictFloat oracle discipline
(clause 1) proven by property test.

## Shipped surface

- `SchemaBuilder.Stat(name, base)` → dense `StatId` (with lookup/duplicate/finite-base validation).
- `Modifier(kind, value)` (Added/Additive/Multi, finite-checked), `ModifierHandle`.
- `Board.AddModifier/RemoveModifier` — insertion ids assigned per board; pair lists in native memory.
- `Board.Recalculate()` — canonicalize (kind, insertion id) → resolve content set → fold →
  broadcast into bound columns at slot×stride.
- Contract fold (exact op sequence, all two-step, no FMA):
  `v = base; v = v + added_i (canonical order); a = 1f; a = a + additive_i; v = v * a; v = v * (1f + multi_i)`.
- Content identity = (stat, canonical sequence of (kind, float bits)); FNV-1a hash +
  full-bytes compare; native open-addressing table; per-set growable member arrays.
- `BindOutput(stat, float* column, stride)` — rebind is explicit; `OutputColumn` tooling read.
- `Clamp.Stat/StatMin/StatMax` — resolves to the bound float column at construction;
  bounds are read per-op with `unchecked((int)f)` truncation, frame-frozen by clause 7 order.
- Slot lifecycle semantics: `Acquire` marks the slot's stats dirty (first recalc
  broadcasts base); `Release` clears modifier lists and set membership (buffs die with
  the slot; reacquired slots start clean).

## Acceptance receipts

- `dotnet build sv.slnx -c Release` — 0 warnings.
- `dotnet test sv.slnx -c Release --no-build` — Passed! 58/58.
- `-p:DefineConstants=SV_CHECKED` — Passed! 58/58.
- Oracle property test: 200 seeded random modifier sets, board fold bits ==
  double-emulated strict two-step oracle bits (`StrictFloat.Add/Mul`, NoInlining).
- Insertion-order proof: Added(1e8,−1e8,1) vs (1,1e8,−1e8) over base 6 fold to 9 vs 8 —
  different bits, same values (canonical order is observable and deterministic).

## Defects found and fixed during this atom (recorded so they are not repeated)

1. `NativeMemory.Alloc(byteCount, alignment)` misuse: every allocation passed
   `count` as byte count (allocated `count` BYTES, not `count*sizeof(T)`). Latent
   since atom 1; detonated here. Fixed at all call sites; helpers now multiply.
2. Uninitialized native memory read as data: `SetTable.buckets` and `setDirty`
   (zero-means-empty) and `Board.live` bitmap were `Alloc`, not `AllocZeroed` —
   caused wild set indices/AV. `outputColumn` (`float*[]`) was cleared with
   `statCount*sizeof(float)` instead of `*sizeof(float*)`, leaving slot 1 garbage
   (only reproducible in full-suite runs — heap reuse).
3. Slot release/acquire stats semantics: release left modifiers (reacquired slots
   inherited buffs) and acquire didn't dirty the empty slot (stale broadcast).
4. C# facts re-learned: pointer types cannot be generic type arguments
   (`ThrowIfNull(int*)`, `Alloc<int*>` illegal — use explicit checks/direct casts);
   `null` is ambiguous between `int*` and `Span<int>` (implicit null-array operator);
   pointer-field structs need unsafe contexts; fields assigned outside ctors cannot
   be `readonly`.
