# Issue 0020 — Atom 17: tape v2 — live-compressed digest body

Filed as GitHub issue #20. Labels: `ai`, `area:compose`, `kind:feat`.

## Problem

The tape body (issue 0016) hashes and stores every sv stat column at full capacity:
~1.2 MB/frame at 100k rows, and a sparse board pays the same — a 4-live-entity board on
a 1M-capacity board would write ~12 MB/frame of dead rows per frame. Determinism of the
live slot space is what the tape is for; dead-row drift is host-invisible state.

## Plan

- `Tape.Version = 2`. Body layout: `[dt bits][axes][buttons][per stat: live rows only,
  ascending slot order (walked via the live words)][live words]`. `BodyLength` uses
  `Board.LiveCount`, so per-frame sizes track spawn/despawn (the per-frame
  `bodyLength` field already supports variable bodies).
- Playback rejects v1 tapes with the existing version diagnostic (v1 has no external
  consumers — the format shipped yesterday).
- Dead rows leave the determinism contract: v2's coverage is the live slot space plus
  the live bitmap; the bitmap itself still pins the slot-space shape.
- New receipts: sparse-board frame size (capacity 64, 4 live → frame well under half
  the v1 body), full-live board unchanged, version-rejection diagnostic.

## Acceptance gate

- All existing tape tests green unchanged (they are digest-internal); new size +
  version facts green; suite green default + `SV_CHECKED`; FMA grep clean.
