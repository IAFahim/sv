# Issue 0017 — Atom 14: bench rate semantics (stop publishing fantasy rows/s)

Filed as GitHub issue #17 (closed — execution record). Labels: `ai`, `area:core`, `kind:perf`.

## Problem

`Sv.Bench.Run()` prints `Rows / (bestUs * 1000)` as "M rows/s" for every scenario, but the
formula is only honest when the frame touches all rows. `stat-recalc` measures one dirty
slot (~0.1 us) and is published as "379 M rows/s"; `input-capture` is an 8 ns capture
published as "7,601 M rows/s". CI now engraves these numbers into the README on every
push (the auto-table from issue-less atom "ci"), so the nonsense is compounded nightly.

## Plan

- `BenchBase` gains `public virtual int RowsPerFrame => Rows;`; scenarios whose frame
  touches one logical row (`stat-recalc`, `input-capture`) declare `1`.
- The rate cell becomes per-scenario semantics: `RowsPerFrame == 1` prints `X ns/op`;
  otherwise `Y M rows/s` exactly as today. Human line, markdown row, and the README
  table header (`rate`) all follow.
- The delta/regression machinery keeps comparing the µs column, so its position must
  not move.

## Acceptance gate

- `dotnet run -c Release --project benchmarks/Sv.Bench` shows ns/op for the two
  single-row scenarios, unchanged M rows/s for the rest.
- `bash .github/scripts/bench-readme.sh` splices the new header + rows; regression
  report still produced against the old table.
- Suite green default + `SV_CHECKED`; FMA grep clean.

## Execution receipts

- `BenchBase.RowsPerFrame` virtual (default `Rows`); `StatRecalcBench`/`InputCaptureBench`
  declare `1`. Rate cell: single-row scenarios print `X ns/op` (stat-recalc **97 ns/op**,
  input-capture **9 ns/op** — previously published as "379 M rows/s" / "7,601 M rows/s");
  row scenarios unchanged (`Rows / (bestUs * 1000)` M rows/s).
- Markdown rows and the README table header now read `rate`; the µs column kept its
  position, so the regression deltas still parse.
- `bash .github/scripts/bench-readme.sh` — table spliced, "No regressions beyond ×1.25".
- `dotnet test sv.slnx -c Release` — 3 projects Passed! (126 + 14 + 6); `SV_CHECKED` —
  Passed! (128 + 14 + 6). FMA grep clean (src/packages/benchmarks/samples).
