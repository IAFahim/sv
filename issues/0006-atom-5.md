# Issue 0006 — Atom 5: SIMD pass — width-invariant vector kernels, pinned stat-bound conversion

Status: closed (2026-11-26, execution record of the sv 2.1 engine, removed in db8dbac on 2026-11-14)

Filed as GitHub issue #6 (closed — execution record). Labels: `ai`, `area:core`, `kind:perf`.

## Shipped surface

- `src/Sv/Simd.cs` (internal) — all SIMD in one file (a Unity/Burst port replaces one
  file; the portable scalar contract lives beside it):
  - `Chunk` / `ChunkW128` / `ChunkW256` / `ChunkScalar` — the contiguous intrinsics
    chunk (uniform or per-row delta, any clamp kind, optional applied twin) as vector
    add + compare/select clamps. Clamps are ternary-select chains only; the inner
    select compares the ORIGINAL sum, so inverted per-row column bounds (lo > hi)
    resolve exactly like the scalar chain (min side wins without a max re-check).
  - `BoolNonZeroWord` / `IntNonZeroWord` (+ width variants) — one 64-row enabled word
    per call from compare-≠0 → movemask lanes; bool bytes normalize during the scan
    (any nonzero byte = true), int lanes give one bit per row.
  - `NormalizeBools` (+ variants) — raw bool bytes → exactly 0/1 bytes.
  - `ApplyButtonWords` (+ variants) — vector ANDNOT edges: `pressed = cur & ~old`,
    `released = old & ~cur`, plus previous/buttons update, shared by live Capture and
    ReplayStep (replay bit-identity is now structural: one kernel, both paths).
- `Board.RunIntrinsicsChunk(int*, ...)` pointer forms route through the width
  dispatcher (Vector256 → Vector128 → scalar by hardware acceleration). Span twins and
  `RunEnabledChunk` stay scalar: enabled runs are already tzcnt run-walks that only
  touch set bits.
- `EventStreams.EmitFromBools(cond, start, count)` and `EmitFromNonZero(values,
  start, count)` full scans became 64-row block scans: vector word per block, shared
  run-walk, scalar tail (no overread past count, no scratch buffer, no allocation).

## Contract pin found by the receipts (bug fixed)

The first width-invariance run FAILED on a StatBounds case: stat column holding
`-1e30f`, scalar `unchecked((int)f)` produced the mod-2^32 wrapped value `-724917978`
(tier-0 conversion helper) while the vector path produced `0x80000000`
(`vcvttps2dq` indefinite). ECMA leaves out-of-range float→int unspecified: tier-0 vs
tier-1 on the SAME machine disagree, and ARM saturates — that breaks replay
bit-identity across machines and phases.

Pin (scalar `Clamp.BoundOf` + vector `Simd.BoundsOf`, identical by construction):
**NaN → 0, saturate to [int.MinValue, int.MaxValue], else truncate toward zero.**
In-range values are unchanged on every arch (truncation and saturation coincide inside
the range); out-of-range/NaN become explicit constants instead of machine artifacts.

## Vectorization dead ends (recorded, do not repeat blindly)

- Stat fold across sets (vertical lanes per set): divergent modifier counts force
  identity padding (`+0.0f`) in exhausted lanes, and `v + 0.0f` rewrites `-0.0f` to
  `+0.0f` — bit-exactness breaks. The canonical left fold stays scalar.
- Broadcast stores: members of a set are arbitrary slots; portable .NET has no vector
  scatter API. Stays one scalar store per member.
- `RunEnabledChunk`: vectorizing would do work on disabled rows the mask exists to
  skip. Stays tzcnt run-walk.
