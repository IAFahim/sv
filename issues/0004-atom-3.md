# Issue 0004 — Atom 3: event streams, fnptr walkers, mask conformance

Status: closed (2026-11-26, execution record of the sv 2.1 engine, removed in db8dbac on 2026-11-14)

Filed as GitHub issue #4 (closed — execution record). Labels: `ai`, `area:core`, `kind:feat`.

## Shipped surface

- `EventStreams.Create(writerCount, bytesPerWriter)` — per-writer native double-buffered
  arenas (two buffers per writer), append with a native CAS lock, growth by doubling
  under the lock; zero allocation per frame after warmup (write offsets reset at swap).
- `Channel<T>` — cold-created typed handle (dense `ushort` type ids, assigned writer
  index); `Write(T)` is the warm native append.
- `Swap()` — end-of-frame (clause 7 last step): snapshot offsets, toggle buffers,
  reset read cursors. `TryReadNext(out type, out payload, out size)` — deterministic
  drain: writer-index order, append order within a writer.
- Walkers (clause 6, all `delegate* unmanaged<int, int, T>` — the portable fnptr core,
  `byte*` condition columns per clause 9 normalization):
  `EmitFromMask(channel, enabled, offset)`,
  `EmitFromBools(channel, cond, start, count)` (+ enabled-mask variant),
  `EmitFromNonZero(channel, values, start, count)` (+ enabled-mask variant),
  `WalkNonZero(values, enabled, offset, visit)` mask-level escape.
- Condition columns are `byte*`: any nonzero byte is true (clause 9); no arithmetic
  byte-to-bit conversion exists anywhere.

## Defect classes found (tests, recorded)

- A 64-bit mask covers exactly 64 rows — 65..128-row cases need both words;
  `1ul << 64` wraps to shift-by-zero (guard with explicit `>= 128` saturation).
- `0b1010` sets bits 1 and 3 — expectations must use bit math, not digit reading.
- Channel type ids follow creation order — tests filtering "type == 0" coupled to
  creation order; drain-all-by-payload is the robust pattern.

## Determinism notes

Within a single writer, order is append order (deterministic single-threaded; the CAS
lock makes concurrent appends safe but their interleave order is scheduler-dependent —
deterministic callers use one writer index per thread). Across writers, drain order is
fixed by writer index. Payloads are unmanaged `T` only; no managed types touch the
stream.
