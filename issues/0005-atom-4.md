# Issue 0005 — Atom 4: input — bit-captured axes, ANDNOT edges, replay ring

Filed as GitHub issue #5 (closed — execution record). Labels: `ai`, `area:core`, `kind:feat`.

## Shipped surface

- `InputState.Create(axes, buttonWords, ringTicks)` — all state in native memory.
- `Capture(uint* axesBits, ulong* buttonWords)` — clause 11: axes stored as raw uint
  bits (never re-read from device, never recomputed); buttons as bit words; edges
  computed in the same step: `pressed = down & ~prev`, `released = ~down & prev`
  (pure ANDNOT — bitwise, float-policy-free).
- Queries: `Down/Pressed/Released(button)` (always-on range guards), `AxisBits(axis)`
  (exact bits), `AxisF(axis)` (bits→float, exact — NaN/±Inf/−0 survive verbatim).
- Ring: fixed capacity, per-tick `{axis bits, button words}`; overwrite-evicts-oldest
  with `OldestRingTick`; `BeginReplay(fromTick)` validates against eviction, resets the
  state machine to the cold start (previous and current zeroed — replay tick 0's edges
  match the original run's edges against the empty initial state), then `ReplayStep()`
  re-feeds ring bits through the exact live Capture path.
- Determinism: replay is bit-identical by construction (same bits, same ANDNOT, same
  initial state) — proven by the replay test, not assumed.

## Acceptance receipts

- `dotnet test sv.slnx -c Release --no-build` — Passed! 75/75.
- `-p:DefineConstants=SV_CHECKED` — Passed! 75/75.
- Replay: 5 random ticks (3 axes incl. full uint range, 64 buttons), full per-tick
  snapshot (axis bits, down word, pressed/released masks) — replay from tick 0 is
  bit-identical, 5/5 ticks.
- Random 16-tick sequence over 128 buttons: pressed/released masks equal the ANDNOT
  reference for every tick, both words.
- Special floats round-trip verbatim: +Inf/−Inf/NaN/−0 (0x7F800000/0xFF800000/
  0x7FC00000/0x80000000).
- Ring eviction: after 10 captures into capacity 4, oldest = 6; replay from 6 works,
  replay from 5 throws.

## Defects found (recorded)

- `BeginReplay` originally kept the final live button state as "previous", so replay
  tick 0's edges differed from the live run's cold-start edges. Fix: replay resets
  current + previous to zero before the first step.
- Test-side bit-math lesson recorded once more: after `0b0110 → 0b0011` the released
  bit is 2 (bit 1 stays down); expectations must be derived from the masks, not read
  off the literals.
