# Issue 0019 — Atom 16: facade csproj nullable alignment (vendoring drift)

Filed as GitHub issue #19. Labels: `ai`, `area:adapter`, `kind:test`.

## Problem

The vendored facade sources (`tests/Sv.Unity.Facade/Burst.cs`, `Entities.cs`) are
verbatim from ecs-kernels and carry `?` nullable annotations, but the local
`Unity.Facade.csproj` I wrote in atom 12 (issue 0015) omits `<Nullable>enable</Nullable>`.
Every CI build then annotates CS8632 ("nullable annotations outside a nullable context")
— files identical, project settings drifted: exactly the subtle divergence the verbatim
rule was meant to prevent.

## Plan

- Enable `<Nullable>enable</Nullable>` in `tests/Sv.Unity.Facade/Unity.Facade.csproj`
  (matches the kernel repo's build settings for the same sources; the `.cs` files stay
  byte-identical — only the project wrapper changes).
- Receipts: warning count before/after on a clean build; suite green default +
  `SV_CHECKED`.

## Acceptance gate

- Zero CS8632 annotations from the facade project on a clean build; suite green both
  configs.
