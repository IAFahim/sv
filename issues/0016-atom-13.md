# Issue 0016 — Atom 13: NorthStar on `Frame.Run` + determinism product (tape)

Filed as GitHub issue #16 (closed — execution record). Labels: `ai`, `area:north-star`, `kind:test`.
Contract touchpoint: new clause 19 — bus 0029 (contract v1.0.4, pending ack).
Umbrella: closes the remaining scope of #2 on the .NET leg.

## Problem

- NorthStar hand-rolls clause 7 (`NorthStarHarness.RunFrame`, lines 189-234),
  hand-rolls its replay receipts (`FrameRecord` bit arrays), and binds into
  `NativeMemory` blocks for pointer stability (tribal knowledge per issue 0012).
  The redesign's user-facing claims (one-call frame, one-line determinism) have no
  acceptance proof until NorthStar runs on them.

## Plan

- Migrate `NorthStarHarness` onto `Sv.Compose`'s `Game`/`Frame.Run` (issue 0014):
  the 3-tick fused test must stay **bit-identical** to the manual harness's recorded
  outputs before the manual path is retired to a comparison test.
- Replace hand-rolled `FrameRecord` with the tape: `game.Record(path)` writes the
  per-frame digest (fixed-order hash over slot space + input ring) plus inputs;
  `game.Playback(path)` re-runs and asserts bit-identity per frame under
  `SV_CHECKED` (release: hash-compare only).
- sv-owned outputs (issue 0012) replace the stability-motivated `NativeMemory`
  blocks; kernel columns stay host-owned.
- Receipts: tl 1.3 published pair + current ecs-kernels facades named in the issue
  file, as 0008/0010 did.
