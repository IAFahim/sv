# Issue 0001 — Atom 1: schema, slots, ternary clamps, intrinsics chunk ops

Atom 1 of the atom plan (README "Atoms" table). Until the GitHub remote exists this
file is the issue; file verbatim on remote creation. Labels there: `ai`, `area:core`,
`kind:feat`.

## Problem

The composition contract needs its state foundation: dense slots, authored schema,
ternary clamps, and the intrinsics chunk surface (`RunIntrinsicsChunk` /
`RunEnabledChunk`, uniform and varying delta) with applied-delta outputs — the layer
Unity-side Essence provides through per-entity hashmaps, here as dense column ops.

## Invariants

- Clauses 2 (ternary clamps), 5 (dense slots, single chunk shape + Span twins), 9
  (normalization N/A yet, no bool ingestion shipped), 12 (pointer guards), 15
  (int-only surface) of the Composition Contract v1.0.
- Intrinsics are int-only; unchecked wrapping addition (documented deterministic);
  `applied = after - before`, `0` for disabled rows in enabled variants.
- Slot lifecycle: initial acquire order ascending, LIFO release reuse, always-on
  misuse guards (double-release, exhaustion, out-of-range, use-after-dispose).
- Guard policy: memory-safety checks always on; range checks under `SV_CHECKED`.
- No FMA, no Min/Max clamps, no explanatory comments, unmanaged data path.
