# Issue 0011 — Atom 8: Enabled-mask geometry decoupling (word spans)

Filed as GitHub issue #11 (open). Labels: `ai`, `area:core`, `kind:feat`.
Contract touchpoint: clause 5/6 amendments — bus 0029 (contract v1.0.4, pending ack).

## Problem (audit receipts)

- `RunEnabledChunk` takes exactly one `ulong` covering 64 slots; `Guard.EnabledRange`
  (`src/Sv/Guard.cs:41-48`) rejects `offset + 64 > capacity`, so a board with
  capacity < 64 cannot use the enabled verb at all — the Minimal sample is forced to
  `Rows = 64` (`sv-examples/samples/Minimal/Program.cs:12`), and a 300-slot board
  cannot address the tail window at offset 256 (`256 + 64 > 300`).
- `contract/mask-fixtures.json` declares `"chunkCapacity": 128` — that constant is
  Unity Entities' `TypeManager.MaximumChunkCapacity = 128` (Entities 6.7.0,
  `Types/TypeManager.cs:705`). sv's core has one host's storage geometry baked in.
- On Frent, a "chunk" from `EnumerateChunks` is the entire archetype buffer — a
  growable `T[]` with no fixed size — so a 300-row archetype needs 157 single-word
  calls per frame, and the host must hand-slice spans to satisfy
  `ChunkSeam.RunEnabledChunk`'s `offsetSlot == start` requirement
  (`src/Sv.Frent/ChunkSeam.cs:128-131`).
- Bus 0027 ruling to fold in: `WriteSkippedZero` (`src/Sv/Board.cs:173-187`) writes
  `applied` for the whole 64-bit word regardless of enabled count — the `applied`
  buffer must cover the full word from `offset`. Signature stays (portable-surface
  rule); document the sizing rule.

## Plan

- Add span forms to `Board` (ptr and `Span` twins, scalar + SIMD paths):
  `RunEnabledChunk(int* value, int delta, in Clamp clamp, ulong* words, int wordCount, int offset, int* applied = null)`
  — window = `wordCount * 64`. The existing 1-word overloads stay (Unity hot path).
- `Guard.EnabledRange` gains the word-count form; `SV_CHECKED` additionally verifies
  that bits past the live rows in the final word are zero.
- `Board.Create(schema, capacity)` rounds capacity up to a word multiple internally;
  `Capacity` reports the rounded value.
- `ChunkSeam.RunEnabledChunk` drops the `offsetSlot == start` requirement in favor of
  the span form (window may begin at any 64-aligned slot base).
- `mask-fixtures.json`: remove `chunkCapacity`; keep `boundaryCounts` (0/1/63/64/65/
  127/128) as word-boundary conformance; regenerate fixture expectations if the
  generator encoded the chunk framing.
- XML doc on every `applied` parameter: "must be sized for the full 64-bit word(s)
  from `offset`; the entire window is written — disabled rows get zero" (bus 0027).

- Zero new allocations on warm paths (issue #9 discipline).
