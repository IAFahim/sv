# Issue 0012 — Atom 9: Binding generations + sv-owned output columns

Filed as GitHub issue #12 (closed — execution record). Labels: `ai`, `area:core`, `kind:feat`.
Contract touchpoint: clause 12 amendment — bus 0029 (contract v1.0.4, pending ack).

## Problem (audit receipts)

- `BindOutput(StatId, float*, stride)` stores the raw pointer verbatim, permanently
  (`src/Sv/Board.Stats.cs:135-150`); every `Recalculate()` writes through it
  (`Board.Stats.cs:291-302`); `Clamp.Stat/StatMin/StatMax` copy the same raw pointers
  into readonly fields at construction (`src/Sv/Clamp.cs:20-92`).
- Clause 12 promises "use-after-rebind detected in checked builds" — no
  implementation exists: the only `SV_CHECKED` code in the library is
  `Guard.ChunkRange`/`Guard.EnabledRange` (`src/Sv/Guard.cs:32-48`). No generation
  counter, no invalidation hook, no stale detection.
- Both reference frameworks resolve at use instead: Entities refreshes lookups every
  frame (`ComponentLookup.Update(ref state)`; `SystemAPI.cs:166-179`), Frent
  documents "treat every `ref T` as invalid after a structural change". A host that
  binds inside a Frent `fixed` scope gets silent UB when the scope ends.
- NorthStar only survives by binding into `NativeMemory.AllocZeroed` blocks —
  discipline that lives in tribal knowledge, not the type system.

## Plan

- Default becomes sv-owned columns: `Board.OutputPtr(StatId)` / `Board.Output<T>`
  re-fetch APIs over storage sv allocates at `Create` (fixed capacity, never moves;
  nothing to invalidate). `Recalculate` broadcasts into sv-owned columns when no
  external binding exists.
- External storage binds through a typed handle: `Board.BindExternal(StatId, float*,
  int stride)` returns a handle capturing the current binding generation; the raw
  `BindOutput` stays as the explicit-advanced form but now bumps the generation.
- `Board.InvalidateBindings()` bumps the generation (called by reconcile, issue
  0013); under `SV_CHECKED`, `Recalculate` and `RunIntrinsicsChunk` throw
  `InvalidOperationException("sv: stale binding — storage moved; rebind")` when a
  captured generation is behind. `Clamp.Stat` captures the generation alongside the
  pointer and is checked on `Apply`.
- XML docs state the doctrine: pointers are valid from bind/generation to the next
  reconcile; hosts owning growable storage must rebind at reconcile.

## Acceptance gate

- Test: external bind → `InvalidateBindings` → `Recalculate` throws under
  `SV_CHECKED`, passes silently in release; sv-owned path needs no bind at all and
  `OutputPtr` reflects broadcast values.
- Test: `Clamp.Stat` captured before invalidation throws on use under `SV_CHECKED`.
- Full suite green default + `SV_CHECKED`; warm alloc still zero; FMA grep clean.
- NorthStar migrates to sv-owned outputs where it used `NativeMemory` blocks for
  stability only (issue 0016 finishes that migration).

## Execution receipts

- Landed: `Board.OutputPtr(StatId)` (sv-owned column, allocated at `Create`, fixed
  capacity, never moves) + `Board.Output(StatId) : Span<float>` managed twin. The
  issue's `Board.Output<T>` shipped non-generic — clause 15 pins effect columns to
  float; a generic would be dead surface.
- `Recalculate` broadcasts into sv-owned columns whenever no external column is
  bound; the external path is unchanged (stride-aware member scatter) behind a
  `Guard.BindingFresh` gate.
- `Board.BindExternal(StatId, float*, int stride)` returns `BindingHandle`
  (`Stat`/`Column`/`Stride`/`Generation`, `IsStale(Board)`); raw `BindOutput` stays
  as the explicit-advanced form — both bump the generation and refresh the stat's
  `boundGeneration` slot.
- `Board.InvalidateBindings()` marks every external binding stale (sentinel −1)
  and keeps the recorded pointers: checked builds throw
  `InvalidOperationException("sv: stale binding — storage moved; rebind")` from
  `Recalculate` (stale broadcast) and from `Clamp.Apply`/`Simd.Chunk` (stale
  captured stat bounds, including `RunIntrinsicsChunk`); release builds keep
  writing through per clause 12 host discipline. All gates are
  `[Conditional("SV_CHECKED")]` — release data path identical.
- `Clamp.Stat`/`StatMin`/`StatMax` resolve external-if-bound, else the sv-owned
  column (captured generation −1 = never stale), and capture the board + per-stat
  generation for the `Apply`-time check; construction fails fast on an already
  stale external column under `SV_CHECKED`. Deviation recorded: the old
  "unbound stat clamp throws ArgumentException" behavior is gone (sv-owned is the
  default column now, and issue 0016's NorthStar migration needs stat clamps over
  sv-owned columns); `StatsTests.ClampStat_UnboundStat_Throws` rewritten as
  `ClampStat_UnboundStat_ResolvesSvOwnedColumn`.
- Doctrine stated in XML docs on `BindOutput`/`BindExternal`/`InvalidateBindings`/
  `OutputPtr`/`BindingHandle`: pointers valid from bind generation to the next
  invalidate/rebind; hosts owning growable storage rebind at reconcile.
- New `tests/Sv.Tests/BindingGenerationTests.cs` (7 facts): sv-owned broadcast +
  zeroed tail + span twin, invalidate→recalculate throws under `SV_CHECKED` /
  silent in release, rebind fresh again, `Clamp.Stat` stale-on-use under
  `SV_CHECKED` / correct clamp in release, handle generation tracking across
  invalidate/rebind/unrelated-stat rebind, sv-owned clamp never goes stale,
  sv-owned recalculate 0 B over 2,000 warm iterations.
- `dotnet test sv.slnx -c Release`: 116/116 + NorthStar 4/4.
  `-p:DefineConstants=SV_CHECKED`: 116/116 + NorthStar 4/4. FMA grep clean.
